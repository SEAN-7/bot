# Plan: 0.8.0, the old commands go and dot-files are delivered quietly

Status: built in 0.8.0. Builds on 0.7.0 (messages and subagents as
files; the old commands kept for one release).

## 1. Remove the old commands

0.7.0 kept `new`, `remove`, `send`, `message`, `messages`, `log`,
`provider describe` and `version`, each printing a notice. 0.8.0 deletes
them.

- `cmd/agent/main.go`: drop their dispatch cases and the `replaced` notice.
  What remains: `daemon`, `_fsio`, `provider install NAME FILE` (root) and
  `help`. An unknown command prints the usage, which points to the manual.
- `internal/cli`: delete `message.go`, `new.go`, `log.go` and the parts of
  `describe.go` only `provider describe` used (keep `RefreshCache`, which
  `provider install` calls), with their tests. If only install remains,
  move it to `internal/install`.
- `help.go`: the usage shrinks to the four commands and a line pointing to
  `/var/lib/agent/manual/manual.md`.
- Manual: remove "The agent command" section's compatibility paragraph.
  Spec: "The binary" loses the 0.7.0 paragraph.
- Known caller: the main agent's cron script `recipes-issue-watch` calls
  `agent send`. The 0.7.0 upgrade note told the agent; before deploying,
  check (read-only) whether the script still calls it, and if so the human
  tells main.

## 2. Dot-files in the inbox are delivered without waking

Today a dot-file in `~/inbox` neither wakes the agent nor is delivered.
From 0.8.0 it does not wake the agent but is delivered: collected with the
other inbox files at the start of the next run and after each command of a
running one. Waking is unchanged: a regular file whose name does not start
with a dot. Spools are unchanged: dot-files there are still ignored, so
the dot-name-then-rename idiom for messages still works.

What it gives agents: a quiet lane. A cron job or script can leave a note
that waits for the next run instead of paying for one.

How an agent's own scripts stage inbox files is the agent's business; the
upgrade note tells it that a dot-file written into `~/inbox` may now be
delivered, half-written if a run collects it mid-write.

### The harness's own inbox writes

The per-user helper's `write` stages every file as `.NAME.random.tmp` in
the target directory and renames it (`internal/fsio/server.go`, `write`).
For inbox files (owner and subagent messages, every harness note) that
temporary file could now be collected mid-write: a partial copy delivered,
labelled `data` rather than `owner` because its name matches no delivery
record, the rename then failing so the message is written again, or lost
for a one-off note; and a temporary file left by a crash delivered
half-written at the next run.

Fix: inbox writes stage in a subdirectory, `inbox/.tmp/`, which collection
skips as it skips every directory, and rename from there (same filesystem,
so still atomic).

- `fsio`: `write` takes an optional staging directory (a new request
  field); empty means the target's own directory, as now.
- Daemon: `writeNote` and inbox delivery (`owner.go`, the `deliver` path)
  pass `inbox/.tmp`. Admission creates it with the other harness
  directories (`private`, 0750); a missing one is created on first use.
  Leftover temporary files in it are removed at admission (each daemon
  start), not at each run start: a run start can coincide with a delivery
  writing there, and leftovers only come from a crash, which a restart
  follows.
- `inbox.go`: split `pending` into the wake test (regular, not
  dot-prefixed) and collection (every regular file; directories, the
  staging directory and `processed/` included, skipped).

```
## 0.8.0
- `agent new`, `agent remove`, `agent send`, `agent message`,
  `agent messages`, `agent log`, `agent provider describe` and
  `agent version` are gone. `agent` has `provider install` (root), `help`

- The harness stages its own inbox files in ~/inbox/.tmp/, which is never
  delivered.
```

## 4. Tests

- Removed commands: `TestRunDispatch` expects "unknown command" for each.
- A dot-file in the inbox does not wake an idle agent, and is delivered
  (labelled `data`) with the next run and after a command of a running run.
- Inbox writes leave nothing in the inbox but the final file; a leftover in
  `inbox/.tmp/` is never delivered and is removed at run start.
- An owner message delivered while a run is collecting is labelled `owner`
  and delivered once.
- Spools still ignore dot-files.

## 5. Prompt cache

The system prompt and `sh` tool do not change.
