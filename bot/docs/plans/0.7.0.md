# Plan: 0.7.0, the CLI becomes files

Status: agreed, not started. Builds on 0.6.0 (the manual, the upgrade
note). One open question is marked below.

## Decision

Remove every agent-facing command. The `agent` binary keeps only what
needs a binary: `agent daemon`, the hidden `agent _fsio` helper, root's
`agent provider install NAME FILE` and `agent help`. `agent version` goes
too: the daemon writes the running version to `~/manual/version` (not
`/var/lib/agent/version`, which records what `install.sh` installed).
Everything an agent, or the human as root with sudo, does with the harness
is a file operation on paths that already exist:

| Today | After |
| --- | --- |
| `agent message "text"` | a regular file in `~/.messages/` (stage under a dot name, then rename) |
| `agent send NAME "text"` | the same in `~/.messages/agents/NAME/` |
| `agent new NAME [CONFIG]` | `mkdir ~/agents/NAME` and a `config.json` in it |
| `agent remove NAME` | `rm -r ~/agents/NAME` |
| `agent messages [NAME]` | `~/journal/messages.jsonl`, `~/journal/agents/NAME/messages.jsonl` |
| `agent log [NAME]` | the newest `~/journal/*Z.jsonl` (or under `agents/NAME/`), and `~/agents/NAME/ERROR` |
| `agent provider describe` | `/var/lib/agent/providers.json` |
| `agent version` | `~/manual/version` |

Root does the same against `/etc/agent/agents/NAME`,
`/etc/agent/.messages/agents/NAME` and `/var/log/agent/NAME/`.

No guarantee is implemented by the CLI: labels, spool ownership, delivery
order, journals and the privilege model are all enforced in the daemon. The
CLI adds fail-fast checks (names, config, empty or oversize text) and
atomic writes; the checks move to daemon time with inbox notes, and atomic
writes become the dot-name-then-rename idiom.

## Daemon changes

1. **Validate a starting `config.json` before a pool user is assigned.**
   Read it through the parent's helper (1 MiB limit), run
   `plugin.ParseConfig` and `plugin.Validate` against
   `/var/lib/agent/providers.json`, and on failure write
   `~/agents/NAME/ERROR` ("config.json: REASON") and the parent note
   "Subagent NAME did not start: config.json: REASON" once per distinct
   content, consuming no user. Re-check each poll; admit as soon as it is
   valid. A missing cache file skips the check (the run's gate reports).
   Today an invalid hand-written starting config is admitted and can only be
   removed.
2. **Stop restoring the `home` link every poll** (`repairHomeLink`,
   `agent.linkErr`). Admission and restarts still write it, and removal
   depends only on the control directory. Then `rm -r ~/agents/NAME` is
   race-free.
3. **Create spool directories**: each child's `.messages/agents/NAME/` at
   admission through the parent's helper (0750), and `/etc/agent/.messages`
   and `.messages/agents` at startup through root's helper, so a human's
   `sudo mkdir` cannot leave root's spool readable by agents. `install.sh`
   also creates them 0700.
4. **Name rule**: `validControlDir` adopts the CLI's rule (one component,
   not starting with `.`, no control characters), for discovery and spools.
5. **Tell the sender about truncation.** A spool file over 64 KiB is
   delivered as its first 64 KiB and "[message truncated]", and the
   sender's inbox gets "Message to NAME was truncated to 64 KiB." (to the
   owner: "Message to your owner was truncated to 64 KiB."), so no failure
   the CLI used to catch becomes silent.
6. **ERROR before admission.** A subagent held back for an invalid starting
   config has no home yet; its reason goes to `~/agents/NAME/ERROR` in the
   control directory, which the spec and manual state explicitly.
7. **The manual version file**: the daemon writes `version` into the manual
   directory with the other files.
8. Move the providers cache code (`LoadProviders`, `RefreshCache`) from
   `internal/cli/describe.go` to `internal/plugin` so the daemon can use it.

## What agents lose

Immediate errors for a bad name, an invalid config or an oversize message.
Instead: an inbox note within about a second (name, config, truncation). `mkdir` still fails at once for a
name that is taken.

## Migration

**Open question:** keep the old commands for one release, or cut at once.

- Recommended: in 0.7.0 the seven commands keep working, do the same file
  operations, and print one line on stderr ("agent send: replaced by
  files; see ~/manual/manual.md (Messages). Removed in 0.8.0."). They are
  deleted in 0.8.0.
- Known caller outside the model: the main agent's cron script
  `~/tools/bin/recipes-issue-watch` runs `/usr/local/bin/agent send recipes`.
  Cutting at once would make it fail silently from cron. The Telegram
  bridge does not use the CLI.
- The 0.7.0 upgrade note (the 0.6.0 mechanism) announces the change at
  each agent's next run.

## Other changes

- `install.sh`: create `main` with `install -d -m 700` and `printf >
  config.json`; choose the model by reading `providers.json`; create root's
  spool directories; next-step hints use file idioms.
- Operator README: `sudo` file idioms for talking to and watching agents
  (a small `send` shell function; `jq`/`tail` for reading).
- Manual: rewrite Messages and Subagents as files; remove "Commands of the
  harness"; Configuration describes `providers.json` directly. Messages say
  delivery is in name order, and the idiom names files by UTC timestamp,
  which sorts in time order.
- Operator README: `$(agent version)` becomes `$(cat /var/lib/agent/version)`.
- Spec: "CLI" becomes "The binary"; Messages lose command names;
  Discovery/Admission gain the config check and spool creation and lose the
  per-poll link repair; a Decision "Everything an agent does with the
  harness is a file".
- The system prompt and `sh` tool do not change, so no cache rebuild.

## Draft release notes

```
## 0.7.0
- Messages are files. A message to your owner is a regular file you own in
  ~/.messages/ whose name does not start with a dot; one to your subagent
  NAME is such a file in ~/.messages/agents/NAME/, which the harness now
  creates when NAME is admitted. They are collected about once a second in
  name order and removed once delivered; a file over 64 KiB is delivered as
  its first 64 KiB followed by "[message truncated]". `agent message` and
  `agent send` wrote exactly these files.
- A subagent is a directory. ~/agents/NAME/ holding a config.json is a
  subagent; removing the directory removes it. The config.json is checked
  against /var/lib/agent/providers.json when it appears, before a user is
  assigned: an invalid one leaves "config.json: REASON" in
  ~/agents/NAME/ERROR and "Subagent NAME did not start: config.json:
  REASON" in your inbox, once per distinct content, and is checked again
  when the file changes. A name starting with "." or holding control
  characters is not a subagent.
- A deleted ~/agents/NAME/home link is no longer put back each second; it
  is written at admission and after a harness restart.
- /var/lib/agent/providers.json is what `agent provider describe` printed.
- A message over 64 KiB is delivered truncated, and its sender gets "Message
  to NAME was truncated to 64 KiB.".
- ~/manual/version holds the running harness version.
- `agent new`, `agent remove`, `agent send`, `agent message`,
  `agent messages`, `agent log`, `agent provider describe` and
  `agent version` still work in this release, do the file operations above,
  print one line on stderr saying so, and are removed in 0.8.0.
```

## Order

1. Providers cache into `internal/plugin`.
2. Pre-admission config check and spool directories (`admit.go`).
3. Root spool directories at startup, name rule, remove link repair
   (`daemon.go`, `admit.go`, `agent.go`).
4. Deprecation line in `cmd/agent/main.go`; help text.
5. `install.sh`.
6. Manual, spec, operator README, release notes.
7. `go vet`, `go test`, privilege tests; release; deploy; read-only checks.
8. 0.8.0: delete the commands, `internal/cli` down to install.
