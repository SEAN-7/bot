---
name: context
description: Request conversation compaction while preserving full history and the current turn.
---

Run `bot-app context compact '{"keepRecentGroups":1}'` to request compaction before the next model response. It preserves the current input and complete tool call/results. The journal is never deleted. Compaction cannot shrink the active turn alone; reduce shell output or choose a larger model when that turn exceeds the input budget. A request survives provider failure and is retried on the next context preparation.

Automatic compaction is checked before every model call. The default trigger is the smaller of 75,000 estimated tokens and the model-derived budget: 50% of a large context window, or 75% for windows below 512,000 tokens, allowing for output. Context app settings `maxInputTokens` or `maxInputChars` override the trigger. Estimates use serialized JSON characters / 4 and reserve space for tools, saved memory, system framing and output. The current request and all its tool activity stay intact, even when larger than the preferred tail.

Compaction follows [Hermes's default compressor](https://hermes-agent.nousresearch.com/docs/developer-guide/context-compression-and-caching/): clear verbose older successful tool output in the summary input, preserve a bounded opening exchange and complete recent tool groups, then make one auxiliary model call for a structured summary. The summary records the latest unresolved request, goal, constraints, progress, decisions, files, next steps, critical facts and session log. Subsequent compactions update the previous summary. Exact identifiers and bounded human-message excerpts are extracted mechanically; a recovery pointer identifies `bot-app memory search`. The original journal is never rewritten or deleted. Failed summaries preserve the prior summary and pending request.

The default recent tail targets 2.5% of the model input window, normally 10,000–25,000 tokens, capped at 20% of the window and the configured compaction budget. It prefers at least 20 messages while that fits, and aligns boundaries to complete tool groups. `keepRecentGroups` overrides this preference; a manual compact request defaults to one recent group. A small opening exchange is retained when there are other older groups to summarize; an oversized opening is summarized so it cannot prevent compaction forever. These budget adjustments and full active-turn retention adapt Hermes's strategy to our one durable conversation.

Saved memory is separate from the conversation summary. Successful compaction advances a durable boundary and refreshes the controller's frozen memory snapshot for the next model request. Retrying or restarting does not lose that snapshot. Compaction does not automatically write conversation facts into saved memory; use the memory app for that.

Before each model response, the controller records a short usage snapshot in the journal, e.g. `History ~57323/1000000 tokens; prior input 37549.` Earlier snapshots remain at their original positions until normal compaction. History is estimated from JSON characters / 4, counting native assistant content once and excluding the system prompt and tool schemas; prior input includes cached tokens from the preceding model call. `?` means unavailable. Growth between snapshots is normal. Retries without new activity reuse the last snapshot. The model adapter presents these records as system messages.
